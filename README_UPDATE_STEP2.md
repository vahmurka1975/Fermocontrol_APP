# ФермоКонтроль — этап 2: резервные копии и экспорт

Основа: main репозитория https://github.com/vahmurka1975/Fermocontrol_APP,
последний показанный GitHub коммит d7a84a5 «Add products, weighing journal and archive».
Архив является обновлением существующего Android-проекта, не самостоятельным проектом и не APK.

## Установка
1. Сохраните текущие изменения проекта отдельным коммитом. Не удаляйте приложение с телефона и не очищайте его данные.
2. Закройте запущенное приложение перед установкой обновления.
3. Распакуйте архив в отдельную папку.
4. Скопируйте папку app из архива в C:\AndroidStudioProjects\Fermocontrol с объединением папок и заменой совпадающих файлов.
   Не удаляйте существующую папку app: архив содержит только изменённые/новые файлы.
5. В Android Studio выполните Sync Project with Gradle Files, затем в терминале корня проекта:

   .\gradlew.bat testDebugUnitTest assembleDebug

6. После успешной сборки установите поверх существующего приложения кнопкой Run.
   Application ID и имя внутреннего файла не изменены; JSON schemaVersion по-прежнему 1.
   Если Android предлагает удалить приложение из-за другой подписи, остановитесь: удаление может стереть журнал.
7. Откройте «Данные» и сразу сохраните JSON-копию вне телефона.

## Новые возможности
В верхней строке рядом с названием приложения добавлена кнопка «Данные».
- «Сохранить JSON-копию»: активные продукты, архив, исторические номера, ID, даты, взвешивания и наблюдения.
- «Экспорт журнала CSV»: все продукты, начальные веса, взвешивания, наблюдения и заметки. Продукты без взвешиваний тоже включены.
- «Восстановить из JSON»: выбор файла, проверка, предварительный подсчёт записей и отдельное подтверждение замены.
- «Вернуть локальную копию»: восстановление состояния перед последней заменой.
- «Сохранить локальную копию в файл»: выгрузка этой копии, в том числе для диагностики повреждённого журнала.

Восстановление ЗАМЕНЯЕТ весь журнал, не объединяет файлы. При каждой замене сохраняется только одна,
последняя локальная копия предыдущего состояния. Даже повреждённый текущий файл сохраняется в исходных байтах.
Если копию записать не удалось, замена не выполняется. Повреждённая локальная копия может быть сохранена в файл,
но её восстановление будет отклонено проверкой. Для возврата доступны только корректные данные.
При ошибке первоначального чтения меню «Данные» остаётся доступным для восстановления;
экспорт текущего журнала и изменение продуктов при этом заблокированы.

JSON ограничен 20 МиБ, 10 000 продуктов и 200 000 взвешиваний. Проверяются версия,
типы обязательных полей, веса, даты, уникальные ID и номера активных продуктов.
Номер архивного и активного продукта может совпадать: архив не занимает номер.
Сохраняется совместимость с JSON предыдущего этапа. Новых разрешений и сетевого доступа нет.
Выбор файлов — системный Android Storage Access Framework; доступность облачных папок зависит от телефона.

## CSV / Excel
UTF-8 с BOM, разделитель «;», десятичная точка, три знака после точки.
Даты — ISO 8601 в UTC (суффикс Z), не локальное время телефона.
При необходимости в Excel: Данные → Из текста/CSV, UTF-8, разделитель «;»,
затем выберите подходящую локаль для чисел с десятичной точкой.
Текстовые значения, начинающиеся с =, +, - или @, защищены от интерпретации как формулы апострофом.
Числовые поля, включая отрицательный процент потери при увеличении веса, остаются числовыми.
CSV — для просмотра и анализа, восстановление возможно только из JSON.
Файлы не зашифрованы; храните их в надёжном месте. При ошибке экспорта удалите неполный файл и повторите.
Локальная копия удалится при удалении приложения/очистке данных и не защищает от потери телефона.

## Ручная проверка на телефоне
1. Создайте продукт и взвешивание с наблюдениями, другой продукт переместите в архив.
2. Сохраните JSON и CSV; проверьте начальный вес, журнал, кириллицу и архив в выгрузке.
3. Добавьте ещё один продукт, восстановите исходный JSON и подтвердите замену.
   Дополнительный продукт должен исчезнуть, история и номера из копии — сохраниться.
4. Через «Вернуть локальную копию» верните состояние с дополнительным продуктом.
5. Отмените выбор файла и отдельно отмените подтверждение замены — журнал не должен измениться.
6. Выберите произвольный текст/JSON другой версии: должна появиться ошибка, текущие данные не меняются.
7. Перезапустите приложение и убедитесь, что восстановленное состояние сохранено.
8. Восстановление из пустой корректной копии намеренно очищает журнал только после подтверждения;
   предыдущий журнал остаётся в локальной копии.

   git push
